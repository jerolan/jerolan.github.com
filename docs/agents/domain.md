# Domain docs

This repo uses a single-context layout.

## Before exploring

Read `GLOSSARY.md` at the repository root and relevant decisions under `docs/adr/`.
If either is absent, proceed silently. Create these documents lazily when domain terms or decisions have actually been resolved.

## Vocabulary and decisions

Use the terms defined in `GLOSSARY.md` in issues, proposals and code. If a necessary concept is missing, reconsider the term or note the gap for domain modeling.
If a proposed change contradicts an existing ADR, identify that ADR and explain why the decision should be reconsidered before overriding it.
